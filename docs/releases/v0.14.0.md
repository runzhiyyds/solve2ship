# Solve2Ship v0.14.0 — Operator quality review / 操作者质量复核

## English

An explicit operator-review mode now connects unlabeled exploration to once-only
final execution and a reviewable delivery decision. The selected artifact, criteria
and review policy freeze before final exposure. Execution seals the paid scope
immediately; saved per-case judgments and one completion decision are separate,
append-only evidence. Accepting all successful final outputs can unlock draft
construction and the usual independent startup/license/export gates. Rejections,
errors, undecided cases and stale snapshots cannot silently pass or reopen.

English/Chinese controls distinguish operator acceptance from label matches and
verified accuracy. Operator identity is self-declared, not authenticated. Validation
feedback and descriptive operator-vs-judge agreement do not become calibrated pruning;
final review never feeds optimization. Default label and hard-constraint guards remain.
Exports retain minimized acceptance provenance without reviewer comments/identities.

Headless local-agent access and redacted model status complement Studio. No new
application dependency or cloud deployment. Real operator judgments are required to
claim actual reviewed quality acceptance; protocol fixtures are not human approvals.

Local evidence (2026-11-10): 178 Python tests with optional schema dependencies
(base: 167 passed, 11 explicit skips) and seven Node tests. A real synthetic Chinese
routing task retained its selected Rules artifact and executed four sealed final
inputs once, without model calls. The owner personally reviewed all four outputs
and explicitly accepted them. No final feedback was used to tune the artifact.
The private bundle ran outside the repository with a minimal environment and passed
six prior-validation HTTP cases plus malformed-request rejection. The source ZIP
passed manifest/license/attribution checks and six Docker HTTP cases. These checks
prove local serving equivalence and self-attested small-sample acceptance, not
business accuracy, authenticated identity or cloud deployment. Structural criteria
are snapshot-bound; separate final structural-check receipts are not yet implemented.

## 简体中文

显式操作者复核方式把无标签探索连接到一次性最终执行和可复核的交付决定。先冻结
方案、规范与复核规则，再暴露最终样例；执行完成立即关闭付费范围。逐条判断和一次
完成决定分别追加留痕。全部成功输出被明确接受后，才可构建草稿并继续独立启动、许可
与导出检查。拒绝、执行错误、无法判断或陈旧快照均不能偷偷通过或重开。

中英界面区分操作者接受、标签一致与已验证准确率；身份为本机自行声明，未认证。
验证反馈及操作者与裁判的一致性仅作描述，不变成自动剪枝校准；最终复核不回流优化。
保留默认标签和硬约束门禁；导出仅保留最小接受来源，不含复核者身份或评论。

无界面本地 Agent 入口与脱敏模型状态和 Studio 并行。不新增应用依赖或云部署。真实
质量接受必须由使用者实际判断；协议夹具不能冒充人工批准。

本机证据（2026-11-10）：安装可选结构校验依赖后通过 178 项 Python、7 项前端测试；
基础环境为 167 项通过、11 项明确跳过。真实合成中文路由任务保留所选规则产物，四条
封存输入仅执行一次，未新增模型调用；所有者亲自复核并明确接受四条输出，没有利用
最终反馈调优。私有包在仓库外、最小环境中通过六条既有验证 HTTP 用例与错误请求拒绝；
源码 ZIP 通过清单、许可、署名及六条 Docker HTTP 用例。这仅证明本机服务一致性与
小样本用户接受，不代表业务准确率、身份认证或云部署。结构规范已绑定快照，独立的
最终结构检查回执仍未实现。
